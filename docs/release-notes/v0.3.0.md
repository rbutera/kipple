# kipple v0.3.0: Linux

kipple now runs on Linux (x86-64 and arm64) as well as macOS, with the same
safety model: one policy gate, dry run by default, the Trash as the only
destination, receipts and restore, home only, no symbolic link followed,
never as root.

## New on Linux

- **The CLI and the terminal UI** (`kipple tui`), with a Linux catalogue:
  the tool caches where each tool keeps them on Linux, other apps' caches in
  `~/.cache` untouched for a week, JetBrains IDE caches, the Maven
  repository, Flatpak app caches, downloaded AI models, and rootless Docker,
  Podman, Flatpak and Snap data (measured only). `kipple rules` lists it.
- **The freedesktop.org Trash** (`~/.local/share/Trash`). Each item gets a
  `.trashinfo` file, so GNOME Files, Dolphin and other file managers show it
  and can restore it; `kipple restore` works too, and reports
  `already_restored` for an item the file manager put back. Moves use
  `renameat2` with `RENAME_NOREPLACE` and never copy.
- **Mount points are boundaries**, bind mounts included: an item that is or
  contains one is skipped (`contains_mount`), the check runs again after
  each move, and an item that picked up a mount on the way is put back. If
  mount points cannot be determined, nothing moves (`mounts_unavailable`).
- **More protection**: the Linux keyrings, browser profiles, password
  managers, `~/.local/state` and the folders named in
  `~/.config/user-dirs.dirs` are protected.
- **Receipts** live in `~/.local/state/kipple/receipts`. kipple uses the XDG
  default locations and warns when an `XDG_*` variable points elsewhere.
- **Static release archives** `kipple_0.3.0_linux_amd64.tar.gz` and
  `kipple_0.3.0_linux_arm64.tar.gz`, listed in the same cosign-signed
  `checksums.txt` as the macOS archives. See "Release binary on Linux" in the
  README. `go install` works on Linux without a C compiler.

The Mac app stays macOS-only: on Linux `kipple-gui` exits and points to
`kipple tui`. A Linux app is planned for v0.3.1.

## For everyone

- **A larger denylist** on both systems (the Linux additions are refused on
  macOS too). Config can still only add protections.
- **`kipple version`** reports the platform: `os` and `arch` in `--json`, a
  `Platform:` line in text.
- **JSON, additive within `schema_version` 1**: receipts can record
  `"mover": "freedesktop"` and `info_ino`; new error codes
  `mounts_unavailable` and `unsupported_platform` (every command except
  `version` and `help` refuses on a system other than macOS and Linux).
- **A run that stops partway** now says what it had already done and names
  the receipt; it offers `kipple restore` only for what is in the Trash.
- **`KIPPLE_STATE_DIR`** inside a protected folder (or the same folder
  reached through a link or a mount) gives a warning; the setting is still
  honoured.
- The macOS catalogue is unchanged from v0.2.0.

## Known limits on Linux

A home on NFS or a FUSE file system without no-replace renames is
scan-only. kipple sees only its own PID and mount namespaces. A mount made
inside a folder after kipple checked it again in the Trash is not seen, so
run `findmnt -R ~/.local/share/Trash` before emptying the Trash. Names of 246
to 255 bytes stay where they are. Details are in docs/safety.md, "On Linux".
